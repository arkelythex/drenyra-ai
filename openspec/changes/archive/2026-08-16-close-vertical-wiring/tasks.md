## How to read this task list

- **Ownership markers**: each checkbox ends with exactly one terminal `<!-- sdd-owner: ... -->`. `implementation` covers RED/GREEN/TRIANGULATE/REFACTOR, code, tests, exports, wiring, and apply-owned verification. `parent` covers only explicit post-apply bounded review and lifecycle-gate actions, grouped separately at the end.
- **Work-unit mapping**: the leading `[W1|W2]` tag marks the work unit a task belongs to; each unit has a clear start, finish, verification, and rollback boundary and maps to one sequential commit inside the single PR.
- **Strict TDD**: every behavior task starts with a failing test (RED) before implementation (GREEN); boundaries follow via TRIANGULATE/REFACTOR. Full suite `bun run test` plus `bun run typecheck` and `bun run build` must pass after each slice.
- **Converter return contract**: both converters return `{ proposals: ReconciliationProposal[]; risks: string[] }`. Risks are human-readable strings preserving the engine's typed code (e.g. `FRACTIONAL_CENTS`, `CROSS_RUC_ACCESS`, `UNCLASSIFIED_DIFFERENCE`, `UNBALANCED_ENTRY`, `ACCOUNT_NOT_IN_CHART`, `INVALID_SCOPE`). Callers surface risks on `ClosePackage.risks`; a non-empty risk never silently drops the corresponding item.
- **Reversibility mapping (deterministic)**: reconciliation drafts → `requireApproval ? "partially-reversible" : "reversible"` (no draft maps to `irreversible`); close entries → `depreciation: "irreversible"`, `provision: "partially-reversible"`, `isr: "irreversible"`, `closing: "reversible"`.
- **Engine inputs (read before apply)**: `bank-reconciliation/` exports `normalizeBankRows(scope, rows): NormalizeResult` (with `.movements`/`.rejected`), `normalizeLedgerRows(...)`, `reconcile(scope, bank, ledger, opts?): Reconciliation` (`.differences`), `buildAdjustments(differences, opts?): AdjustmentDraft[]`, `AdjustOptions { requireApproval?, approvalOverrides? }`, `BankReconciliationError { code }`. `close-calculations/` exports `computeDepreciation(scope, assets, policy): CloseEntry[]`, `computeProvisions(scope, inputs, policy): CloseEntry[]`, `computeProvisionalIsr(scope, input, policy): { entry: CloseEntry; cedula: IsrCedula }`, `closeResultAccounts(scope, balances, chart): CloseEntry[]`, `CloseEntry { id, scope, lines: CloseLine[], kind }` (balanced: sum(debits) === sum(credits)). The engine `Scope` is `{ ruc, period }`; the close `CloseScope` is `{ ruc, period, companyId }` — the converters pass `{ ruc, period }` and are scoped to the close's own scope. The provisional-ISR returns `{ entry, cedula }`; exactly ONE proposal derives from `entry`, the cédula is not a proposal.
