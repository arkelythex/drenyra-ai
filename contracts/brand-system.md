# Contract: brand-system

> Version: 0.2 · Status: DRAFT · Transport-agnostic.
>
> The **visual authority of the ecosystem is Drenyra apps/web**: the token
> pipeline `tokens.dtcg.json → generated tokens` (DTCG), with class-based
> `.dark` / `.light` themes and the cyan/violet accent system declared in
> `apps/web/src/index.css` ("DRENYRA CYAN/VIOLET VISUAL SYSTEM"). Every other
> ecosystem surface — Drenyra AI, Drenyra Pi, Drenyra Engram, Drenyra Skills,
> Guardian Angel — mirrors exactly this system, in **both themes**. No
> ecosystem product invents its own palette.

The **brand-system** is the single source of truth for the visual identity of
the Drenyra ecosystem. v0.1 was based on a stale "generated (minimal)" token
CSS (legacy blue `#1a73e8`, dark-only) and is **superseded**: the canonical
source is the DTCG token pipeline of apps/web, which ships **dark + light
themes** and a **cyan/violet accent system**. Drift between ecosystem products
is the exact error class this contract eliminates.

## Purpose

- Give every ecosystem product the **same design system as Drenyra apps/web**,
  in both themes, from the same token values.
- Define what **may** be generated by AI image models and what **must** remain
  hand-authored vector.
- Make "no drift" an enforced property: the conformance checker fails CI on any
  color outside the canonical set (vectors, zero tolerance) or outside palette
  coverage (raster, bounded tolerance), in either theme.
- Keep the brand verifiable: AI-generated assets carry C2PA provenance
  metadata — the brand itself follows the receipt thesis.

## Canonical tokens

Machine truth lives in [`contracts/brand-system/tokens.json`](brand-system/tokens.json)
and mirrors the DTCG primitives exactly. **No derived tokens are invented** —
every variant (hover/active/dim, text tiers, states) already exists in the
source.

### Accent system (cyan + violet)

| Accent | `base` | `hover` | `active` | `dim` |
| --- | --- | --- | --- | --- |
| `cyan` | `#3CE6D8` | `#6AEFE4` | `#2ECFC2` | `#1F8A80` |
| `violet` | `#9B7FE8` | `#B8A2F0` | `#6B54A8` | `#7B66C0` |

Cyan is the **primary brand accent** (the "verified/proven" color); violet is
the secondary/companion accent. The AI halo system of apps/web
(`color-mix(in oklch, #3CE6D8 14%, transparent)` / `#9B7FE8`) is reserved for
runtime UI, not static brand assets.

## Gradients

Gradients blend **only between canonical tokens**. Two per theme:

| Gradient | Dark stops | Light stops | Use |
| --- | --- | --- | --- |
| `surface` | canvas → surface → surface-2 | canvas → surface | Banners, hero panels |
| `brand` | cyan.base → violet.base | cyan.active → violet.active | Display/hero text, brand marks |

## Typography

| Role | Stack |
| --- | --- |
| Display | Space Grotesk, Inter, Geist, sans-serif |
| Sans (UI/body) | Inter, Geist, Plus Jakarta Sans, ui-sans-serif, system-ui, sans-serif |
| Mono (code, receipts, hashes) | Geist Mono, JetBrains Mono, ui-monospace, monospace |

Hash identifiers, receipt codes, and ledger values render in **mono** — the
typographic signature of verifiability. Mirrors `apps/web` `--font-sans` /
`--font-mono`.

## Radius and spacing

- Corner radius: `0.5rem` (8px) — apps/web token. Pills (fully rounded) are
  allowed only for tag chips; cards use the system radius.
- Spacing follows the apps/web token scale (8px grid).

## Themes in static assets

- Static brand assets (SVG banners) **must render correctly in both themes**,
  resolved via `@media (prefers-color-scheme: light)` with CSS custom
  properties; the conformance checker resolves `var(--…)` declarations from
  `<style>` blocks and validates every declared hex in both theme blocks.
- Raster AI assets default to the **dark theme surface**; a light-theme variant
  is optional but must follow the light token set exactly.

## Vector assets — the non-negotiables

- **Logo, wordmark, favicon, app icon, CLI art: always SVG/vector, hand-authored
  or traced, never AI raster.** They are reproduced in code, favicons, and
  print; raster cannot be re-derived.
- SVG brand assets are validated with **zero tolerance** against the union of
  both themes + accents + `#ffffff` + `#000000`. Opacity is the only free
  parameter.
- **Banned hues** (the drift this contract kills): legacy blue `#1a73e8` and
  family, off-system cyan `#22d3ee` (Drenyra cyan is `#3CE6D8`), royal blue
  `#041c78`, and any warm beige/ember tones.

## AI-generated images — allowed, bounded

AI image models (ChatGPT Images 2.0 / `gpt-image-1`) are allowed for **concept
exploration and decorative assets**, never for identity primitives.

Allowed: banner/hero compositions, documentation illustrations, social previews.
Forbidden: logo, wordmark, favicon, icons (see vector rules above).

Rules (enforced by the conformance checker on raster assets):

1. **Palette-only.** Every sampled pixel must be within `tolerancePerChannel`
   (±24 per channel) of a canonical color (union of both themes + accents); at
   least `coverageRequired` (85%) of sampled pixels must be in palette. The
   checker reports the off-palette colors so the image can be regenerated with
   a corrected prompt.
2. **No critical text.** Product names, claims, and version numbers live in SVG
   or code, never baked into raster.
3. **Dark, professional, architectural.** No cartoon, no mascot; gradients only
   between canonical tokens.
4. **Aspect ratios.** banner 1400×460, social preview 1200×630, icon 512×512.
5. **Provenance.** Generated assets must keep C2PA provenance metadata and the
   imperceptible watermark. Drenyra brand images are verifiable, exactly like
   its receipts.

### Prompt template (ChatGPT Images 2.0)

The canonical **ecosystem prompt set** lives in
[`docs/assets/brand/gpt-image-prompts.md`](../docs/assets/brand/gpt-image-prompts.md)
— one optimized prompt per product (Drenyra, Drenyra AI, Drenyra Pi, Drenyra
Engram, Drenyra Skills, Guardian Angel), each composed of the shared
Ecosystem DNA block plus a product-specific motif. The generic template below
is for ad-hoc explorations:

```text
Design a dark, professional, architectural banner for an enterprise accounting
verification platform. Background: deep navy canvas #0B0E11 with a subtle
blueprint grid and soft glows in cyan #3CE6D8 and violet #9B7FE8 at low
intensity. Accent colors ONLY: cyan #3CE6D8 (and lighter #6AEFE4), violet
#9B7FE8 (and lighter #B8A2F0), success green #4ADE94, muted blue-gray #A8B0BC.
All gradients must blend exclusively between these colors — no blue #1a73e8,
no other cyan, no purple outside the violet set, no warm tones, no white
glows. Visual motif: an abstract ledger/hash-chain and a verified receipt with
a checkmark; geometric, no cartoon, no mascot. No text in the image. Aspect
ratio 1400:460. Keep C2PA provenance metadata.
```

## Conformance

- **Vectors (SVG):** zero tolerance against the canonical union; `var(--…)`
  references and `<style>` declarations are resolved and validated in both
  theme blocks.
- **Raster (PNG):** palette coverage with bounded per-channel tolerance; any
  image below `coverageRequired` fails.
- **Palette shape:** both themes (dark + light) and both accents must be
  present and hex-valid in `tokens.json`; the conformance set is the union.
- **CI:** `bun run brand:conformance` runs in CI (job `brand-conformance`) over
  `docs/assets/brand/**`; consuming repos run the same checker over their own
  brand assets.
- **Adding a brand asset** is a contract-visible change: add it, run the
  conformance check locally, let CI pin it.

- v0.1 (DRAFT, superseded) — canonical palette derived from the stale
  "generated (minimal)" token CSS (blue `#1a73e8`, dark-only).
- v0.2 (DRAFT) — rebuilt on the **DTCG token pipeline of apps/web**: dark +
  light themes and the cyan/violet accent system with exact values; banner
  migrated to dual-theme CSS variables; conformance resolves theme-aware CSS
  variables; AI rules and prompt template updated. v0.1's blue palette is
  banned.
- Freeze to v0.3 requires: every consuming repo (Drenyra Pi, Drenyra Engram,
  Guardian Angel) passes the conformance checker on its brand assets in both
  themes, and documented drift examples (drenyra-engram banner) are regenerated
  or removed.
