# Contract: brand-system

← [Contracts index](README.md) · [README](../README.md)

Read this contract before authoring visual assets. The token file, not an image sampled by eye, defines the palette.

> Version: 0.4 · Status: DRAFT · Transport-agnostic.
>
> The **visual authority of the ecosystem is the Dreamcoder Workbench** —
> canonical tokens at `dreamcoder-dots/DreamcoderThemes/dreamcoder/tokens.json`
> (Dreamcoder Light Cocoa/Lúcuma, Dreamcoder Dark OLED-aware, Dusk transition; readability
> before decoration, WCAG/APCA). Every ecosystem surface — Drenyra AI, Drenyra
> Pi, Drenyra Engram, Drenyra Skills, Drenyra Console, Guardian Angel — mirrors
> exactly this system, in **both themes**. No ecosystem product invents its own
> palette.

The **brand-system** is the single source of truth for the visual identity of
the Drenyra ecosystem. v0.1 (legacy blue `#1a73e8`, dark-only) and v0.2
(cyan/violet "AI glow" identity) are **superseded**: the canonical source is
the Dreamcoder Workbench token system — warm editorial surfaces (Lúcuma/Cocoa),
dark ink, and a restrained institutional accent set. The design direction is
**less "AI startup", more editorial institutional system**: no neon glow, no
generic futuristic AI imagery, no robot/brain/circuit clichés. Technology
should feel advanced because the information is extraordinarily well
organized, not because it has glow.

## Purpose

- Give every ecosystem product the **same design system**, in both themes,
  from the same canonical token values.
- Define what **may** be generated by AI image models and what **must** remain
  hand-authored vector.
- Make "no drift" an enforced property: the conformance checker fails CI on any
  color outside the canonical set (vectors, zero tolerance) or outside palette
  coverage (raster, bounded tolerance), in either theme.
- Keep the brand verifiable: AI-generated assets carry C2PA provenance
  metadata — the brand itself follows the receipt thesis.

## Canonical tokens

Machine truth lives in [`contracts/brand-system/tokens.json`](brand-system/tokens.json)
and mirrors the Dreamcoder Workbench tokens exactly. **No derived tokens are
invented** — every variant (hover/active/dim, text tiers, states) already
exists in the source.

cyan/violet "AI glow" identity (v0.2) is **banned**.

## Gradients

Gradients blend **only between canonical tokens**. Two per theme:

| Gradient | Dark stops | Light stops | Use |
| --- | --- | --- | --- |
| `surface` | canvas → surface → surface-2 | canvas → surface | Banners, hero panels |
| `brand` | accent → accent-2 (indigo → lavender) | cocoa.active → terracotta.active | Display/hero text, brand marks |

## Typography

| Role | Stack |
| --- | --- |
| Display | Space Grotesk, Inter, Geist, sans-serif |
| Sans (UI/body) | Inter, Geist, Plus Jakarta Sans, ui-sans-serif, system-ui, sans-serif |
| Mono (code, receipts, hashes) | Geist Mono, JetBrains Mono, ui-monospace, monospace |

Hash identifiers, receipt codes, and ledger values render in **mono** — the
typographic signature of verifiability.

## Radius and spacing

- Corner radius: `0.5rem` (8px). Pills (fully rounded) are allowed only for tag
  chips; cards use the system radius.
- Spacing follows an 8px grid.

## Themes in static assets

- README and documentation visuals ship as a **Light/Dark pair** — one file per
  theme, embedded with `<picture>` or the `#gh-light-mode-only` /
  `#gh-dark-mode-only` fragments — so each reader sees the composition drawn for
  their theme. The conformance checker resolves `var(--…)` declarations and
  validates every declared hex in either file.
- Raster AI assets default to the **Dreamcoder Light** editorial surface; a
  Dreamcoder Dark variant is optional but must follow the dark token set
  exactly.

## Vector assets — the non-negotiables

- **Logo, wordmark, favicon, app icon, CLI art: always SVG/vector, hand-authored
  or traced, never AI raster.** They are reproduced in code, favicons, and
  print; raster cannot be re-derived.
- SVG brand assets are validated with **zero tolerance** against the canonical
  union (both themes + accents + `#ffffff` + `#000000`). Opacity is the only
  free parameter.
- **Banned hues** (the drift this contract kills — all v0.2 legacy identity):
  old cyan `#3CE6D8` and family, old violet `#9B7FE8` and family, the v0.2
  dark ladder `#0A0A0A`/`#121212`/`#1A1A1A`, the superseded v0.3 Anthracite
  Steel ladder (`#070A13` and its steel-blue family), legacy blue `#1a73e8`,
  off-system cyan `#22d3ee`, royal blue `#041c78`. Warm cocoa/lúcuma tones and
  the Dreamcoder Dark OLED canvas `#000000` are canonical, not banned.

## AI-generated images — allowed, bounded

AI image models (ChatGPT Images 2.0 / `gpt-image-1`) are allowed for **concept
exploration and decorative assets**, never for identity primitives.

Allowed: banner/hero compositions, documentation illustrations, social previews.
Forbidden: logo, wordmark, favicon, icons (see vector rules above).

Rules (enforced by the conformance checker on raster assets):

1. **Palette-only.** Every sampled pixel must be within `tolerancePerChannel`
   (±24 per channel) of a canonical color (union of both themes + accents); at
   least `coverageRequired` (92%) of sampled pixels must be in palette. The
   checker reports the off-palette colors so the image can be regenerated with
   a corrected prompt.
2. **No critical text.** Product names, claims, and version numbers live in SVG
   or code, never baked into raster. Branding appears in the hero only; other
   diagrams are editorial and text-light.
3. **Editorial, institutional, restrained.** Dreamcoder Light paper surfaces,
   dark ink, one strong hero object, generous negative space. No neon, no
   generic futuristic AI, no robot/brain/circuit clichés, no floating HUD
   cards. Gradients only between canonical tokens.
4. **Aspect ratios.** banner 1400×460 (≈3.04:1), social preview 1200×630,
   icon 512×512.
5. **Provenance.** Generated assets must keep C2PA provenance metadata and the
   imperceptible watermark. Drenyra brand images are verifiable, exactly like
   its receipts.

The canonical **ecosystem prompt set** lives in

The generic template below is for ad-hoc explorations:

```text
Design an editorial, institutional banner for an accounting verification
platform in the Dreamcoder Light visual language: warm ivory paper background
#F3EADC, mineral cream surfaces #FFF7EA, dark warm ink #17120D, and accents
ONLY cocoa #824F16, terracotta #A7471C, sage #315B31, diagnostic teal #0D4A68

negative space on the left, restrained editorial composition — like a
precision engineering schematic printed on warm technical paper. No neon, no
glow, no generic futuristic AI, no robot/brain/circuit clichés, no dashboard
HUD cards. Gradients only between the canonical colors. No text in the image
(the README carries the name). Aspect ratio 1400:460. Keep C2PA provenance
metadata.
```

## Conformance

- **Vectors (SVG):** zero tolerance against the canonical union; `var(--…)`
  references and `<style>` declarations are resolved and validated.
- **Raster (PNG):** palette coverage with bounded per-channel tolerance; any
  image below `coverageRequired` fails.
- **Palette shape:** both themes (dark + light) and both accents (cocoa +
  terracotta) must be present and hex-valid in `tokens.json`; the conformance
  set is the union.
- **CI:** `bun run brand:conformance` runs in CI (job `brand-conformance`) over
  `docs/assets/brand/**`; consuming repos run the same checker over their own
  brand assets.
- **Adding a brand asset** is a contract-visible change: add it, run the
  conformance check locally, let CI pin it.

## Freeze record

- v0.1 (DRAFT, superseded) — canonical palette derived from the stale
  "generated (minimal)" token CSS (blue `#1a73e8`, dark-only).
- v0.2 (DRAFT, superseded) — cyan/violet "AI glow" identity on dark
  anthracite; OLED-black dark ladder; Dreamcoder Light warm-ivory light theme;
  dual-theme CSS variables and fused gradient banners.
- v0.3 (DRAFT, superseded) — rebuilt on the **Dreamcoder Workbench canonical
  tokens**: Anthracite Steel dark, Cocoa/Lúcuma light, cocoa/terracotta
  accents, and the editorial institutional direction (readability before
  decoration). The v0.2 cyan/violet/OLED identity is banned; legacy assets
  removed.
- v0.4 (DRAFT) — re-synchronized with the current Dreamcoder Workbench: the
  dark theme becomes **Dreamcoder Dark** (OLED-aware `#000000` canvas,
  near-black surface ladder, indigo/lavender accent pair); Dreamcoder Light is
  unchanged. Documentation visuals ship as Light/Dark pairs. The conformance
  set now collects the cocoa/terracotta accents (v0.3 still collected the
  banned cyan/violet keys), and `tokens.schema.json` moves from v0.2 to v0.4.
  Approved by the owner on 2026-10-28.
- Freeze to v0.4 FROZEN requires: every consuming repo (App Web, Pi, Engram,
  Skills, Drenyra Console, Guardian Angel) passes the conformance checker on its
  brand assets in both themes. The freeze gate is `bun run brand:ecosystem` —
  it must report every repo `PASS` (exit 0).
