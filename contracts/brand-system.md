# Contract: brand-system

> Version: 0.1 · Status: DRAFT · Transport-agnostic.
>
> The **visual authority of the ecosystem is Drenyra** (the Command Center):
> `apps/web/src/lib/design-tokens` is the source of the canonical palette below.
> Every other ecosystem surface — Drenyra AI, Drenyra Pi, Drenyra Engram,
> Drenyra Skills, Guardian Angel — derives its visuals from this contract, never
> from its own colors.

The **brand-system** is the single source of truth for the visual identity of
the Drenyra ecosystem. It exists because the ecosystem is a **system**: three
repos shipped three different blue families before this contract existed
(Drenyra `#1a73e8`, drenyra-ai cyan `#22d3ee`/purple `#a78bfa`, drenyra-engram
royal blue `#041c78`). That drift is the exact class of error this contract
eliminates — the same way a frozen contract eliminates schema drift.

## Purpose

- Give every ecosystem product one canonical palette, typography, radius, and
  gradient system derived from the Command Center.
- Define what **may** be generated by AI image models and what **must** remain
  hand-authored vector.
- Make "no drift" an enforced property: the conformance checker fails CI on any
  color outside the canonical set (vectors, zero tolerance) or outside palette
  coverage (raster, bounded tolerance).
- Keep the brand verifiable: AI-generated assets carry C2PA provenance
  metadata — the brand itself follows the receipt thesis.

## Canonical palette

Machine truth lives in [`contracts/brand-system/tokens.json`](brand-system/tokens.json).
The checker loads it and re-derives derived tokens from base tokens.

| `primary` | `#1a73e8` | Brand blue — CTAs, active states, hero gradients |
| `primary-foreground` | `#ffffff` | Text on primary |
| `secondary` | `#f5a623` | Brand amber — accents, secondary actions |
| `secondary-foreground` | `#000000` | Text on secondary |
| `background` | `#0a0e27` | App surface, dark brand surface |
| `foreground` | `#e0e0e0` | Primary text on dark surfaces |
| `muted` | `#4a5568` | Skeleton bars, inactive fills |

| `border` | `#1e3a5f` | Strokes, dividers, card borders |
| `destructive` | `#ef4444` | Errors, destructive actions |

**No color outside this set** (base + derived + `#ffffff` + `#000000`) may appear
in a vector brand asset. In particular, cyan (`#22d3ee`, `#67e8f9`, `#06b6d4`),
purple (`#a78bfa`, `#c4b5fd`, `#8b5cf6`), and royal blue (`#041c78`, `#0c38ec`)
are **banned** — they are the historical drift this contract kills.

byte drift — a hand-edited derived value is a contract violation, not a choice.

## Gradients

Only three gradients exist in the ecosystem. A gradient is defined by its stops,
never by arbitrary colors.

| Gradient | Stops | Use |
| --- | --- | --- |
| `surface` | background → surface-1 → surface-2 | Banners, hero panels |
| `brand` | primary → primary-light | Display/hero text, brand marks |
| `accent` | secondary → warning-light | Sparingly: highlights, badges |

## Typography

| Role | Stack |
| --- | --- |
| Display | Space Grotesk, Inter, Segoe UI, sans-serif |
| Sans (UI/body) | Inter, Segoe UI, Helvetica Neue, Arial, sans-serif |
| Mono (code, receipts, hashes) | Geist Mono, JetBrains Mono, SFMono-Regular, monospace |

Hash identifiers, receipt codes, and ledger values render in **mono** — it is the
typographic signature of verifiability.

## Radius and spacing

- Corner radius: `0.5rem` (8px) — system token. Pills (fully rounded) are allowed
  only for tag chips; cards use the system radius.
- Spacing follows the Command Center's token scale; brand assets mirror it (8px
  grid).

## Vector assets — the non-negotiables

- **Logo, wordmark, favicon, app icon, CLI art: always SVG/vector, hand-authored
  or traced, never AI raster.** They are reproduced in code, favicons, and
  print; raster cannot be re-derived.
- Banner/hero compositions may be SVG (preferred) or AI-generated raster under
  the AI rules below.
- SVG brand assets are validated with **zero tolerance**: every `fill`, `stroke`,
  `stop-color`, and `color` must be in the canonical set. Opacity is the only
  free parameter.

## AI-generated images — allowed, bounded

AI image models (ChatGPT Images 2.0 / `gpt-image-1` are the current generation)
are an allowed tool for **concept exploration and decorative assets**, never for
identity primitives.

Allowed: banner/hero compositions, documentation illustrations, social previews.
Forbidden: logo, wordmark, favicon, icons (see vector rules above).

Rules (enforced by the conformance checker on raster assets):

1. **Palette-only.** Every sampled pixel must be within `tolerancePerChannel`
   (±24 per channel) of a canonical color; at least `coverageRequired` (85%) of
   sampled pixels must be in palette. The checker reports the off-palette colors
   so the image can be regenerated with a corrected prompt.
2. **No critical text.** Product names, claims, and version numbers live in SVG
   or code, never baked into raster. Decorative abstract lettering is allowed.
3. **Dark, professional, architectural.** No cartoon, no mascot, no gradients
   outside the three canonical ones.
4. **Aspect ratios.** banner 1400×460, social preview 1200×630, icon 512×512.
5. **Provenance.** Generated assets must keep C2PA provenance metadata and the
   imperceptible watermark. This is a feature, not a limitation: Drenyra brand
   images are verifiable, exactly like its receipts.

### Prompt template (ChatGPT Images 2.0)

```text
Design a dark, professional, architectural banner for an enterprise accounting
verification platform. Background: deep navy (#0a0e27) with a subtle blueprint
grid. Accent colors ONLY: brand blue #1a73e8, lighter blue #5f9def, amber
#f5a623, success green #34d399, muted blue-gray #8892b0. Visual motif: an
abstract ledger/hash-chain and a verified receipt with a checkmark; abstract
geometric composition, no cartoon, no mascot. No text in the image. Aspect
ratio 1400:460. Keep C2PA provenance metadata.
```

## Conformance

- **Vectors (SVG):** zero tolerance. Any hex outside the canonical set fails.
- **Raster (PNG):** palette coverage with bounded per-channel tolerance; any
  image below `coverageRequired` fails.
- **Derivation:** the checker recomputes all derived tokens from base and fails
  on byte drift vs `tokens.json`.
- **CI:** `bun run brand:conformance` runs in CI (job `brand-conformance`) over
  `docs/assets/brand/**`; consuming repos run the same checker over their own
  brand assets.
- **Adding a brand asset** is a contract-visible change: add it, run the
  conformance check locally, let CI pin it.
